ACID Transaction: Steps 11–19 execute inside a database transaction. If payment fails, the entire booking is rolled back — no partial state.

Sequence: AI Vehicle Damage Inspection & Assessment

Satisfies: ASR-03 (P-2 full inspection ≤15s), ASR-04 (S-1 encrypted photos), FR-18 to FR-22

sequenceDiagram autonumber actor User as 👤 Renter / Owner participant UI as 🖥️ Damage Scanner Page participant GW as 🛡️ API Gateway + Rate Limiter participant API as ⚙️ AI Damage API Route participant Groq as 🧠 Groq AI — LLaMA 3.2 Vision participant Vault as 📁 Object Storage Vault participant DB as 🗄️ Database User->>UI: Upload car photo (drag and drop or file input) UI->>UI: Preview image and validate file type (JPG/PNG/WEBP) UI->>GW: POST /api/ai/damage (FormData: image file) GW->>GW: Check rate limit by IP (5 requests per minute — Upstash Redis) alt Rate limit exceeded GW-->>UI: 429 Too Many Requests UI-->>User: Show "Too many scans — please wait 60 seconds" else Within rate limit GW->>API: Forward request with image file API->>API: Extract image from FormData to ArrayBuffer API->>API: Convert to base64 string — get MIME type API->>Vault: Store uploaded photo (encrypted, AES-256) for audit trail Vault-->>API: Return permanent storage URL API->>Groq: POST {model: llama-3.2-11b-vision, messages: [{role: user, content: [image, prompt]}]} Note over Groq: LLaMA analyzes image pixels:
Detect damage zones (bumpers, doors, hood, fenders, windshield)
Classify severity: none / minor / moderate / severe
Estimate repair cost in EGP adjusted for vehicle make/model Groq-->>API: JSON response {damage_detected, severity, zones[], total_repair_cost_egp, confidence} API->>API: Parse JSON — validate structure alt AI returns invalid JSON API->>API: Use safe fallback default response end API->>DB: INSERT INTO damage_reports (booking_id, severity, zones, cost_egp, photo_url) DB-->>API: Report saved — ID: dmg_4421 API-->>GW-->>UI: 200 OK — Full damage report JSON UI-->>User: Display damage card with severity badge (color coded) UI-->>User: Show zone-by-zone breakdown with EGP repair costs UI-->>User: Show deposit recommendation (Full Refund / Partial / Confiscate) end
AI Model: Groq LLaMA 3.2 Vision (11B parameters) analyzes the image. Response time target: ≤ 15 seconds including upload and processing (ASR-03 P-2).
Rate Limiting: 5 AI scans per minute per IP. Prevents API abuse and controls Groq API costs. Returns 429 with retry-after header.
Fallback Safety: If Groq returns malformed JSON (rare), the API returns a safe default response so the UI never crashes.

sequenceDiagram autonumber actor Owner as 👤 Vehicle Owner participant UI as 🖥️ Client UI participant GW as 🛡️ API Gateway participant Book as 📅 Booking Service participant Fin as 💰 Finance Service participant Strat as ⚖️ Deposit Strategy Engine participant Pay as 💳 Payment Gateway participant DB as 🗄️ Database actor Renter as 👤 Renter Owner->>UI: Confirm return mileage and acknowledge damage assessment UI->>GW: POST /api/rentals/rent_9481/complete GW->>Book: Complete rental workflow request Book->>DB: SELECT damage_report, security_deposit FROM bookings WHERE id='rent_9481' DB-->>Book: Deposit held: $1,000 — Damage severity: minor — Repair cost: $120 Book->>Fin: Calculate final deposit settlement (deposit=$1000, repair=$120, severity=minor) Note over Fin,Strat: Strategy Pattern: Select PartialDeductionStrategy based on severity=minor Fin->>Strat: PartialDeductionStrategy.calculate(depositAmount=1000, repairCost=120, severity=minor) Strat-->>Fin: DepositOutcome — Deduction: $120 | Refund: $880 | Status: partial_deduction Fin->>Pay: Capture $120 from held deposit (compensation to owner) Pay-->>Fin: Capture authorized — Transaction ID: cap_7731 Fin->>Pay: Release remaining $880 to renter payment method Pay-->>Fin: Refund confirmed — Transaction ID: ref_9921 Fin->>DB: BEGIN TRANSACTION Fin->>DB: UPDATE bookings SET status='completed', deposit_status='partial_refund', deduction=120 Fin->>DB: INSERT INTO payment_transactions (cap_7731, ref_9921, amounts, timestamps) DB-->>Fin: COMMIT — Transaction committed (ACID) Fin-->>Book-->>GW-->>UI: Display final settlement invoice UI-->>Owner: Show settlement: $120 credited to your account Book-)Renter: SMS and email: "$880 deposit refunded — $120 deducted for front bumper damage" Book-)Owner: SMS and email: "$120 damage compensation credited — Vehicle available again"
Strategy Pattern in Action (Step 7): The FinancialService does NOT contain deposit calculation logic itself. It delegates to the selected DepositStrategy implementation at runtime. If a new rule is needed (e.g., "luxury vehicles: 150% penalty"), only a new strategy class is written — zero changes to Booking or Finance service code. This satisfies ASR-05 Modifiability (Scenario M-1).
